# Garbage Collection

```autohotkey
#Include lib\ahk#.ahk

CS.GC()               ; Force a full GC cycle (waits for finalizers)
bytes := CS.Memory()  ; Managed heap size in bytes

; Format nicely
mb := Round(bytes / (1024 * 1024), 2)
MsgBox("Heap: " mb " MB")
```

## When to Use

- Long-running scripts processing large data
- After releasing many proxies (set the variables to `""`), then `CS.GC()`
- Before memory-intensive operations

Call `proxy.Dispose()` on objects that implement `IDisposable` (streams, connections, ...) instead of waiting for the GC. Two helpers make that automatic:

```autohotkey
; scoped: fn(obj) runs, then Dispose, even if fn throws; returns fn's value
text := CS.Using(CS.System.IO.StreamReader("C:\Temp\notes.txt"), (r) => r.ReadToEnd())

; dispose when the last AHK reference to this proxy is released
stream := CS.System.IO.File.OpenRead("C:\Temp\notes.txt").AutoDispose()
stream := ""                                ; disposed now
```

Use `AutoDispose()` only on the **one** proxy that owns the object; a second proxy of the same object (a fluent call that returns `this`, say) would find it already disposed. `Dispose` works on any object with a public parameterless `Dispose()`, even one that does not implement `IDisposable`.

## Watching for leaks: CS.Stats

```autohotkey
s := CS.Stats()             ; Map
s["ManagedHeapBytes"]       ; managed heap, without forcing a collection (call CS.GC() first for a stable number)
s["Delegates"]              ; registered event/callback delegates: back to 0 (or its start value) after Off / Unregister
s["PendingAsyncTasks"]      ; async slots not yet collected: 0 when every promise has completed
s["QueuedCallbacks"]        ; worker-thread callbacks waiting for the AHK thread: 0 when drained
s["ResolvedTypes"], s["OverloadCacheEntries"], s["BoundCallCacheEntries"]   ; cache sizes; they stay flat for repeated calls
```

See the [API reference](15_api_reference.md#csstats). `tests\test_stress.ahk` uses these counters to check that proxies, delegates and async slots are released.

## Notes

- Each proxy keeps its .NET object alive until the AHK variable holding it is released.
- .NET AppDomains cannot be unloaded in CLR v4. `CS.GC()` runs a managed collection, but compiled and loaded assemblies stay in memory until the process exits. The disk cache is not affected.
- `CS.Memory()` reports the managed heap only, not native memory or the AHK side.
